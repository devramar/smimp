# Documentation Strategy

this document explains how this repository keeps its documentation maintained.

do NOT add notes to the `docs/` folder. if you wish to create docs, please use `.docs/`
that folder is intentionally not git tracked, and this folder is reserved for human approved documentation to be copy/pasted over from there.

## Code-wise Documentation
Dos and Donts:
 - You DO NOT need to document the comings and goings of each method call.
 - you SHOULD comment the high level ideas of what your code does.
    - if you're writing a class, a succinct comment before the class declaration explaining what it does, and why it does that is necessary.
